### `LinkStyle`

How a link is drawn.

Set it as `GptMarkdownStyleSheet(link: LinkStyle(…))` on the widget, or in `GptMarkdownThemeData` for the whole app. Every field is optional; an unset one falls back to the theme, then to the default.

| Field | Type | Description |
|---|---|---|
| `color` | `Color?` | Link colour. Defaults to the theme's `linkColor`. |
| `hoverColor` | `Color?` | Colour under the pointer. Defaults to `linkHoverColor`. |
| `decoration` | `TextDecoration?` | Defaults to an underline. |
| `decorationThickness` | `double?` | Underline thickness. Defaults to the font's. |
| `fontWeight` | `FontWeight?` | Weight of link text. Defaults to the surrounding weight. |

| Member | Type | Description |
|---|---|---|
| `merge(LinkStyle? other)` | `LinkStyle` | This style, with any unset field taken from `other`, field by field. |
| `resolve(ColorScheme scheme)` | `LinkStyle` | This style with every remaining default filled in. |
| `copyWith({…})` | `LinkStyle` | A copy with the given fields replaced. |
| `static lerp(LinkStyle? a, LinkStyle? b, double t)` | `LinkStyle?` | Linearly interpolates between two styles. |

<details>
<summary><code>resolve</code>: more</summary>

Colours fall back to the theme's `linkColor` and `linkHoverColor`, which
remain the app-wide way to set them.

</details>

### `inlineLinkBuilder`

Builds the span for a link, replacing the default rendering.

Wins over `linkBuilder` when both are set. Returning a span rather
than a widget keeps the link on the text baseline, wrapping across
lines and selectable — none of which a `WidgetSpan` can do.

```dart
typedef InlineLinkBuilder = InlineSpan Function(LinkBuildDetails details);
```

### `autolink`

Whether bare URLs, `www.` hosts, email addresses and `<...>` autolinks
become links. Defaults to true.

Bare autolinks follow the GFM autolink extension; `<...>` autolinks follow
CommonMark §6.5. Turn this off to render URLs as plain text — for
untrusted input where an accidental tap target is unwelcome.

```dart
bool autolink
```

### `autolinkSchemes`

Extra URL schemes linked **without** `<>`.

`http`, `https`, `mailto` and `xmpp` are always linked. Anything else has
to be opted into, because a bare `foo://bar` in prose is usually not meant
as a link:

```dart
GptMarkdown(text, autolinkSchemes: const {'myapp'})
```

This does not affect `<...>` autolinks, which accept any scheme as
CommonMark specifies — the author wrote the brackets deliberately.

```dart
Set<String> autolinkSchemes
```

### `linkBuilder`

:::caution[Deprecated]
Use inlineLinkBuilder. Will be removed in 2.0.0.
:::

Builds a widget for a link.

Used only when `inlineLinkBuilder` is null. The result is wrapped in a
`WidgetSpan`, which is the shape that made this hook a problem —
prefer `inlineLinkBuilder`, or `styleSheet`'s `LinkStyle` when you
only want to restyle.

```dart
typedef LinkBuilder = Widget Function(
  BuildContext context,
  InlineSpan text,
  String url,
  TextStyle style,
);
```

### `LinkBuildDetails`

What the link builder is told about one `[label](url)` or autolink.

| Member | Type | Description |
|---|---|---|
| `context` | `BuildContext` | The element this construct is being built in. |
| `config` | `GptMarkdownConfig` | The configuration in force at this point in the document. |
| `style` | `TextStyle` | The text style in effect for this construct, fully resolved. |
| `url` | `String` | The link target — `/docs/a`, `https://x.dev`, `mailto:a@b.c`. As written, except that backslash escapes and entity references are decoded (CommonMark), and a reference link (`[text][label]`) carries the URL of its `[label]: url` definition. Never otherwise resolved or normalised. |
| `label` | `String` | The label as plain text. |
| `labelSpans` | `List<InlineSpan>` | The label, already parsed and styled with `style`. |
| `linkStyle` | `LinkStyle` | The resolved `LinkStyle` — colour, hover colour, decoration, thickness and weight, with `GptMarkdownTheme` fallbacks already applied. |
| `isAutolink` | `bool` | Whether the package found this as a bare URL rather than as `[…](…)`. |
| `onTap` | `VoidCallback?` | Invokes `GptMarkdownConfig.onLinkTap` for this link, or null when no handler is set. |
| `hoverStyle` | `TextStyle` | `style` recoloured with `LinkStyle.hoverColor`, for `TappableTextSpan.hoverStyle`. |
| `defaultSpan({TextStyle? style, List<InlineSpan>? children})` | `InlineSpan` | Exactly what a link renders as when no builder is given. |
| `asWidgetSpan(…)` | `InlineSpan` | `child` in a placeholder wrapped exactly the way the deprecated `LinkBuilder`'s result is, with `onTap` attached. |

<details>
<summary><code>config</code>: more</summary>

Read `GptMarkdownConfig.scope` from it to tell a link in a table cell
from one in ordinary content, and `GptMarkdownConfig.textDirection` or
`GptMarkdownConfig.textScaler` when a widget of your own needs them.
`TableBuilder` and `OrderedListBuilder` already take a whole config for
the same reason.

</details>

<details>
<summary><code>style</code>: more</summary>

A builder never has to guess a default: this is what the construct would
have been drawn with, its own style already applied over the surrounding
one.

</details>

<details>
<summary><code>label</code>: more</summary>

This is what `GptMarkdownConfig.onLinkTap` receives as its second
argument. For an autolink it is the URL itself. It is **not** a link
title: the parser reads `[text](url "title")` titles into `MdLink.title`,
but they do not reach builders yet.

</details>

<details>
<summary><code>labelSpans</code>: more</summary>

The parse has happened by the time a builder runs, in the
`MarkdownScope.linkLabel` scope, so `[**bold** link](url)` arrives as the
spans that render it. An autolink's label is one plain run, deliberately:
re-parsing a URL would let `ItalicMd` eat the underscores out of
`https://example.com/a_b_c`.

</details>

<details>
<summary><code>linkStyle</code>: more</summary>

Passed alongside `style` so a builder can reach a value a `TextStyle`
cannot carry. `hoverColor` is the one that exists today.

</details>

<details>
<summary><code>onTap</code>: more</summary>

Hand it to `TappableTextSpan.onTap` — or to `defaultSpan`, which does it
for you — rather than calling `onLinkTap` yourself, so the arguments stay
right when they change.

</details>

<details>
<summary><code>defaultSpan</code>: more</summary>

Returning this from `InlineLinkBuilder` is a no-op, which makes it the
safe starting point: keep it, then change one thing.

`style` replaces the style on the **container** span. It does not
restyle the label, because `labelSpans` were already built with their own
styles — bold inside a link stays bold, and a colour set here does not
reach them. To recolour the label, rebuild it and pass `children`:

```dart
inlineLinkBuilder: (link) => link.defaultSpan(
  children: [TextSpan(text: link.label, style: link.style.copyWith(
    color: link.url.startsWith('https://') ? null : Colors.orange,
  ))],
),
```

For a widget instead of a span, see `asWidgetSpan`.

</details>

<details>
<summary><code>asWidgetSpan</code>: more</summary>

The escape hatch for a link that genuinely has to be a widget. It cannot
wrap across lines, is skipped by text selection, is one opaque character
to the streaming reveal, and does not paint on iOS when nested inside
another placeholder — prefer a span where the design allows.

</details>

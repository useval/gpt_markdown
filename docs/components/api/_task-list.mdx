### `CheckboxStyle`

How a task-list checkbox or radio button is drawn.

Set it as `GptMarkdownStyleSheet(checkbox: CheckboxStyle(…))` on the widget, or in `GptMarkdownThemeData` for the whole app. Every field is optional; an unset one falls back to the theme, then to the default.

| Field | Type | Description |
|---|---|---|
| `size` | `double?` | Box size. Defaults to the Material default. |
| `checkedColor` | `Color?` | Fill when checked. Defaults to the Material default. |
| `uncheckedColor` | `Color?` | Border when unchecked. Defaults to the Material default. |
| `checkColor` | `Color?` | The tick itself. Defaults to the Material default. |
| `borderRadius` | `Radius?` | Corner rounding of a checkbox. |
| `gapAfterBox` | `double?` | Space between the box and its label. Defaults to 5. |
| `interactive` | `bool?` | Whether taps are accepted. Defaults to false. |

| Member | Type | Description |
|---|---|---|
| `merge(CheckboxStyle? other)` | `CheckboxStyle` | This style, with any unset field taken from `other`, field by field. |
| `resolve(ColorScheme scheme)` | `CheckboxStyle` | This style with every remaining default filled in. |
| `copyWith({…})` | `CheckboxStyle` | A copy with the given fields replaced. |
| `static lerp(CheckboxStyle? a, CheckboxStyle? b, double t)` | `CheckboxStyle?` | Linearly interpolates between two styles. |

<details>
<summary><code>resolve</code>: more</summary>

Colours left null use Material's own checkbox and radio defaults, so the
widgets keep following the app theme.

</details>

### `onCheckboxChanged`

Called when a task-list checkbox is tapped.

Only fires when `CheckboxStyle.interactive` is set — Markdown checkboxes
render the source text, so they are read-only unless you opt in.

```dart
void Function(bool value)? onCheckboxChanged
```

### `InlineCodeStyle`

How inline `code` is drawn.

Set it as `GptMarkdownStyleSheet(inlineCode: InlineCodeStyle(…))` on the widget, or in `GptMarkdownThemeData` for the whole app. Every field is optional; an unset one falls back to the theme, then to the default.

| Field | Type | Description |
|---|---|---|
| `fontFamily` | `String?` | The monospace family. Defaults to the bundled JetBrains Mono, the same family fenced code blocks use. |
| `fontFamilyPackage` | `String?` | The package `fontFamily` is shipped in. |
| `fontFamilyFallback` | `List<String>?` | Fallback families, used when a glyph is missing from `fontFamily`. |
| `fontSizeFactor` | `double?` | Code font size relative to the surrounding text. Defaults to `0.94`. |
| `fontWeight` | `FontWeight?` | Weight of the code text. Defaults to the surrounding weight. |
| `color` | `Color?` | Colour of the code text. Defaults to `ColorScheme.onSurface`. |
| `backgroundColor` | `Color?` | Chip fill. Defaults to a tint of `ColorScheme.onSurface` — 10% on a light scheme, 14% on a dark one, since a light tint over a dark surface reads weaker than the same tint over a light one. |
| `borderColor` | `Color?` | Chip outline. Defaults to a tint of `ColorScheme.onSurface` — 28% light, 34% dark. |
| `borderWidth` | `double?` | Outline thickness. Defaults to `1.0`. Zero disables the outline. |
| `borderRadius` | `Radius?` | Corner radius. Defaults to `Radius.circular(4)`. |
| `padding` | `EdgeInsets?` | Space between the text and the chip edge. Defaults to `EdgeInsets.symmetric(vertical: 1)` — no horizontal padding, so the chip hugs the code and the surrounding words keep their normal spacing. |
| `boxHeightStyle` | `ui.BoxHeightStyle?` | How the height of each line fragment is measured. |

<details>
<summary><code>fontFamilyPackage</code>: more</summary>

Defaults to `gpt_markdown` **only** while `fontFamily` is also null. Set
`fontFamily` to a family of your own and this stays null unless you say
otherwise, which is what you want for an app-level font.

</details>

<details>
<summary><code>fontSizeFactor</code>: more</summary>

Monospace faces read larger than proportional ones at the same point size,
so a small reduction keeps the line rhythm even.

</details>

<details>
<summary><code>borderColor</code>: more</summary>

Set to `Colors.transparent` for a fill with no outline.

</details>

<details>
<summary><code>padding</code>: more</summary>

Horizontal padding, when set, is applied to the outer edges of a wrapped
run only — a chip continuing onto the next line is not padded at the
break, so the two halves read as one run.

</details>

<details>
<summary><code>boxHeightStyle</code>: more</summary>

Defaults to `ui.BoxHeightStyle.tight`, which follows the code font's own
metrics. Use `ui.BoxHeightStyle.strut` for chips that fill the line box.

</details>

| Member | Type | Description |
|---|---|---|
| `merge(InlineCodeStyle? other)` | `InlineCodeStyle` | This style, with any unset field taken from `other`, field by field. |
| `resolve(ColorScheme scheme)` | `InlineCodeStyle` | This style with every null field filled in from `scheme`. |
| `copyWith({…})` | `InlineCodeStyle` | A copy of this style with the given fields replaced. |
| `static lerp(InlineCodeStyle? a, InlineCodeStyle? b, double t)` | `InlineCodeStyle?` | Linearly interpolates between two inline code styles. |
| `applyTo(TextStyle base)` | `TextStyle` | `base` with this style's typography applied. |

<details>
<summary><code>merge</code>: more</summary>

Per field, not per object: a style setting only `color` keeps `other`'s
font, padding and border.

</details>

<details>
<summary><code>applyTo</code>: more</summary>

Colours other than `color` are painted by `InlineCodeDecoration`, not
carried on the `TextStyle` — that is what lets the chip have a radius, an
outline and padding while the text still wraps.

</details>

### `inlineCodeBuilder`

Builds the span for inline `` `code` ``, replacing the default chip.

Reach for `inlineCodeStyle` first — it covers font, colours, outline,
radius and padding without a builder. Use this when the styling has to
depend on the code itself.

```dart
typedef InlineCodeBuilder = InlineSpan Function(
  BuildContext context,
  String code,
  TextStyle style,
  InlineCodeStyle codeStyle,
);
```

### `inlineCodeStyle`

How inline `code` is drawn, for this widget only.

Null fields fall back to the ambient `ColorScheme`, so a single field is
enough:

```dart
GptMarkdown(
  text,
  inlineCodeStyle: const InlineCodeStyle(fontFamily: 'GeistMono'),
)
```

Set `GptMarkdownThemeData.inlineCode` instead to restyle the whole app.

```dart
InlineCodeStyle? inlineCodeStyle
```

### `highlightBuilder`

:::caution[Deprecated]
Use inlineCodeBuilder. Will be removed in 2.0.0.
:::

Builds a widget for inline `` `code` ``.

Used only when `inlineCodeBuilder` is null, and kept so 1.1.x code keeps
compiling. The result is wrapped in a baseline-aligned `WidgetSpan`,
which is the shape that made this hook a problem: it cannot wrap across
lines, is skipped by text selection, and does not paint on iOS inside a
link label.

Reach for `inlineCodeStyle` if you only want to restyle inline code, or
`inlineCodeBuilder` if you need to build the span yourself.

```dart
typedef HighlightBuilder = Widget Function(
  BuildContext context,
  String text,
  TextStyle style,
);
```

### `HeadingStyle`

How a `#` heading is drawn.

Set it as `GptMarkdownStyleSheet(heading: HeadingStyle(…))` on the widget, or in `GptMarkdownThemeData` for the whole app. Every field is optional; an unset one falls back to the theme, then to the default.

| Field | Type | Description |
|---|---|---|
| `textStyle` | `TextStyle?` | Applied on top of the level style from the theme. |
| `padding` | `EdgeInsetsGeometry?` | Space around the heading. Defaults to none. |
| `showDivider` | `bool?` | Whether a rule is drawn under the heading. |
| `dividerColor` | `Color?` | Colour of that rule. |
| `dividerThickness` | `double?` | Thickness of that rule. |
| `dividerPadding` | `EdgeInsetsGeometry?` | Space around that rule. |

| Member | Type | Description |
|---|---|---|
| `merge(HeadingStyle? other)` | `HeadingStyle` | This style, with any unset field taken from `other`, field by field. |
| `resolve(ColorScheme scheme)` | `HeadingStyle` | This style with every remaining default filled in. |
| `copyWith({…})` | `HeadingStyle` | A copy with the given fields replaced. |
| `static lerp(HeadingStyle? a, HeadingStyle? b, double t)` | `HeadingStyle?` | Linearly interpolates between two styles. |

<details>
<summary><code>resolve</code>: more</summary>

Heading defaults live on `GptMarkdownThemeData` as `h1`-`h6`,
`autoAddDividerLineAfterH1` and the `hrLine*` fields. Anything left null here
keeps using those, so existing themes keep working unchanged.

</details>

### `headingBuilder`

Replaces the whole heading widget, including the rule an h1 draws.

Reach for `styleSheet` first — `HeadingStyle` covers the text style,
padding and the rule without giving up the default structure.

```dart
typedef HeadingBuilder = Widget Function(
  BuildContext context,
  int level,
  Widget content,
  HeadingStyle style,
);
```
